# Message craft

Injected when the run is drafting, sequencing or replying.

## The first message

Purpose: earn a reply. Not to inform, not to impress, not to pitch.

Shape (in this order, and nothing else):
1. One specific, verifiable observation about *their* work — something that
   proves you looked, that a template could not have produced.
2. One question they can answer in a sentence, whose answer changes what you
   would build.

Constraints: under 60 words. No attachment. No link unless they asked. No
credentials-dropping about L2. No "quick call?" as the first ask. No percentage
claims. No second paragraph.

Failure test: if the message would read identically with another prospect's
name substituted, it is a template — rewrite it or do more research.

## Follow-ups

At most two, each carrying **new** information, never a "just bumping this".
- Follow-up 1 (day 4–6): a second observation or a relevant, specific artifact.
- Follow-up 2 (day 12–15): the honest close — "I'll stop here; if the timing
  changes, my door is open." Then move to `nurture`.

Three unanswered touches means the answer is no. Record it and stop.

## Reply handling

Classify the reply, then respond to the class, not to the words:

| Class | Signal | Next move |
|---|---|---|
| `open` | a real question back | answer in one message; propose the smallest test |
| `curious-vague` | "interesting, tell me more" | one concrete example + one question; no dossier |
| `price-first` | "how much?" | scope before price: name the pilot, then the range |
| `defer` | "not now" | ask what would make it a "now"; set a nurture date |
| `objection` | a specific doubt | check the objection library; answer the real concern |
| `no` | explicit decline | thank, close, record. Never re-queue. |

Record every reply as a `touch` with the class in `outcome`, and any new fact
as a `signal`.

## Discovery (25–30 minutes, when it gets that far)

- 0–8: their business as they describe it — offers, audience, what sells.
- 8–18: where the work actually hurts. What do people ask for that they cannot
  deliver? What do they refuse to monetize, and why?
- 18–25: show at most two product surfaces, 2–3 screens each. Storyboards, not
  demos.
- 25–30: propose the smallest validation test. Never a build commitment.

Write the discovery output as signals and a gate decision, not as prose notes.
Prose notes do not survive a context reset; records do.
